# Connex 前端布局与视觉设计基线

本文是 Connex 第一阶段前端界面的设计基线，约束布局、主题、配色、密度、组件选择和交互状态。实现与本文冲突时，先更新本文并说明原因，再修改代码，不能让不同功能模块各自形成一套视觉规则。

## 1. 产品视觉方向

Connex 是高频使用的桌面生产力工具，不是营销页或数据看板。界面采用“终端优先、信息紧凑、表面安静、状态明确”的设计语言：

- 以中性灰构成工作区层级，祖母绿只用于品牌、主操作、焦点和活动状态。
- 保留当前近乎平面的专业工具感；停靠面板使用边框分隔，不堆叠卡片和阴影。
- 不使用渐变、玻璃拟态、霓虹光晕、大面积品牌色或装饰性背景纹理。
- 不刻意模仿“黑底绿字”的黑客风格。终端内容负责表现 ANSI 色彩，应用框架保持克制。
- 系统窗口操作始终由原生窗口装饰提供；应用全局栏统一承载品牌、当前上下文、传输和设置，不得在各功能页重复放置这些入口。

当前暗色应用壳的三栏方向继续沿用，但它只是起点；本文中的浅色主题、自适应和传输区域规则才是完整目标。

应用安装包图标使用仓库根目录的 `app-icon.png` 作为无损母版，由 Tauri 生成 `src-tauri/icons` 中的平台尺寸。母版保持正方形透明画布、深蓝圆角底板和青蓝至绿色的终端字形，不进行自动重绘、描边简化或调色；界面内“不使用渐变”的约束不适用于操作系统展示的应用图标。

## 2. 信息架构与主布局

应用固定由系统窗口区域、应用全局栏、连接导航、会话工作区、远程文件和状态栏组成。传输任务从全局栏打开浮层，不再占用终端的固定高度：

```text
┌────────── 系统窗口区域：macOS 原生交通灯；Windows / Linux 原生标题栏与窗口按钮 ──────────┐
├──────────────── 应用全局栏：Connex / 当前上下文 / 传输 / 设置 ──────────────────────────┤
├──────── 连接侧栏 ────────┬─────────── 工作区标签栏 ────────────┬── 文件操作 ──┤
│ 标题 / 搜索 / 新建       │ 侧栏开关 / 新建 / 会话与页面标签     │ SFTP 工具栏   │
│                          ├─────────────────────────────────────┼──────────────┤
│ 连接名称列表             │                                     │ 路径与文件表格 │
│                          │              终端                   │              │
│                          │                                     │              │
├──────────────────────────┴─────────────────────────────────────┴──────────────┤
│ 全局状态栏：连接摘要 / 安全存储 / 版本                                         │
└───────────────────────────────────────────────────────────────────────────────┘
```

尺寸基线：

| 区域         |        默认值 | 允许范围与行为                                     |
| ------------ | ------------: | -------------------------------------------------- |
| 应用窗口     |  `1280 × 800` | 最小 `960 × 640`                                   |
| 应用全局栏   |        `44px` | 固定高度；macOS 与原生标题栏重叠，其他平台位于其下 |
| 连接侧栏     |       `248px` | 可调整 `224–320px`；收起后为 `0px`                 |
| 工作区标签栏 |        `28px` | 固定高度；单标签默认宽 `144px`，可横向滚动         |
| 中央工作区   |        自适应 | 宽屏时至少保留 `560px`；空间不足时优先隐藏文件面板 |
| 远程文件面板 |       `320px` | 可调整 `280–520px`，支持完全关闭                   |
| 传输浮层     | `512 × 448px` | 固定尺寸，内容超出后只在当前状态列表内部滚动       |
| 状态栏       |        `24px` | 固定高度，跨窗口底部                               |

宽度策略：

- `≥ 1180px`：连接侧栏、中央工作区和远程文件可以同时停靠显示。
- `960–1179px`：文件面板改为右侧 `Sheet`，不持续挤压终端；连接侧栏仍可由用户完全收起。
- 窗口缩小时不压缩控件字号和行高。空间让渡顺序是文件面板、侧栏文字、非关键工具按钮。
- 面板尺寸由可拖动分隔线调整并记忆，但第一次启动始终使用默认值。

窗口与全局栏规则：

- Tauri 窗口始终开启系统装饰（`decorations: true`）。关闭、最小化、最大化等窗口操作必须由操作系统提供，前端不得绘制、染色或模拟任何平台的窗口按钮。
- macOS 使用 `titleBarStyle: Overlay`、`hiddenTitle: true` 和 `trafficLightPosition`，让原生交通灯覆盖在 `44px` 应用全局栏左侧；全局栏必须为交通灯预留固定空间，并让交通灯与文字品牌在视觉上垂直居中。
- Windows 和 Linux 保留各自完整的原生标题栏及窗口按钮，应用全局栏紧贴在系统标题栏下方。不得为了视觉一致而隐藏系统标题栏。
- 文字品牌 `Connex` 与当前上下文位于全局栏左侧，不放置品牌图标；传输和设置位于右侧。当前上下文使用纯文字，只显示活动连接名或当前全局页面，不添加前置装饰图标，过长时截断。
- 只有 macOS 全局栏内的非交互空白区域设置为窗口拖动区；按钮、输入框和浮层触发器不能成为拖动区。Windows 和 Linux 由原生标题栏负责拖动与双击缩放。
- 全局栏中的图标按钮必须支持键盘操作，并提供 Tooltip 和可访问名称。
- 应用菜单栏和系统窗口菜单继续使用 Tauri/操作系统原生菜单；连接、标签、终端和远程文件等 WebView 业务区域统一使用 shadcn `ContextMenu`，不得回退到浏览器默认右键菜单。连接列表与远程文件面板的空白区域保留对应业务菜单；应用全局栏与工作区标签栏的空白区域只屏蔽浏览器菜单，不展示无业务含义的菜单。
- 系统关闭按钮发起退出时默认显示紧凑 `AlertDialog`，明确提示 SSH 会话和文件传输将被关闭。弹窗提供“记住我的选择”复选框；只有勾选后确认退出才保存“以后直接退出”，取消不能改变偏好。确认操作使用 destructive 样式，保存或关闭失败时保持弹窗并展示错误。

第一阶段不做本地/远端双栏文件管理器。用户通过系统文件选择器或拖入文件面板上传，通过系统保存位置下载；这样可以让终端始终是主工作区。

## 3. 主要界面和承载方式

### 3.1 连接与会话

- 连接侧栏顶部固定为 `40px` 工具栏：左侧标题“连接列表”，右侧依次放置 `28px` 搜索和新建图标按钮，不设置“最近使用”或“全部连接”等二级范围导航。
- 搜索默认隐藏；点击搜索按钮后，在工具栏下方展开一个占满侧栏内容宽度的 `32px` 输入框并自动聚焦。搜索支持名称、主机和用户名的部分匹配；关闭搜索时清空查询，避免隐藏过滤条件。
- 连接列表使用紧凑单行布局而不是卡片墙；每项只显示 `SquareTerminal` 图标和 `11px` 连接名称，单击只聚焦，双击发起连接，键盘聚焦后按 Enter 同样连接。当前 SSH 标签对应的连接项使用强调背景和主色图标同步显示选中状态；设置等非 SSH 页面不选中连接。编辑入口仅在悬停或键盘聚焦时出现。主机、用户名、端口和认证方式留在编辑表单中，不在列表重复展示。
- 连接项右键菜单提供连接、编辑、复制不含凭据的连接地址和删除；删除仍必须经过 `AlertDialog` 确认。
- 侧栏收起后宽度为零，不显示标题、工具按钮或连接项，也不能让隐藏控件参与键盘导航；终端与设置内容不为侧栏控制预留空白，也不允许浮层按钮覆盖内容。
- 侧栏开关固定在工作区标签栏最左侧，作为 Connex 的“侧栏铰链”：使用 `24 × 24px` 的紧凑 `PanelLeftOpen` / `PanelLeftClose` 图标按钮，紧邻 `24 × 24px` 新建按钮，之后通过垂直 `Separator` 进入标签区；所有状态必须提供 Tooltip、可访问名称和展开状态。
- 新建或编辑连接使用居中的紧凑 `Dialog`，宽度上限约 `512px`；它是一个短暂的完整输入任务，不占用或挤压终端工作区。标题只保留一句说明，连接名称与用户名使用双列排列，主机与端口合并为一个地址输入组，认证方式使用内容宽度的紧凑分段选择，不把每个字段包进独立卡片。表单输入框、认证选择和底部按钮统一使用 `32px` 紧凑规格；表单在小窗口内滚动，标题和底部操作区保持可见。密码认证在创建时必须输入密码，私钥口令可选；秘密由 Rust 加密后保存在本机数据库，编辑时留空表示保留已保存值。
- 密码和私钥口令使用 `InputGroup` 内嵌小眼睛按钮。按钮默认弱化，在输入框 hover 或 focus-within 时显现；指针悬停或键盘聚焦按钮期间显示当前输入。编辑已有连接且字段为空时才按需解密本机凭据，离开按钮立即恢复掩码并清除临时读取值。
- 首次主机指纹、指纹变化、删除连接、删除远程文件和覆盖文件属于安全或破坏性决策，使用 `AlertDialog`，不能用 Toast 代替确认。
- 新建会话进入顶部标签栏。SSH 标签依次显示状态点、`SquareTerminal` 图标、`11px` 连接名和关闭操作；页面标签文字同为 `11px`。断线后标签保留，用户可重连或关闭。
- 网络中断或 keepalive 超时后统一显示“连接已丢失”。终端区域必须保留常驻状态面板，并提供“重新连接”和“关闭标签”操作，直到用户完成其中一项；不得只使用会自动消失的 Toast 表达连接终态。
- SSH 标签右键菜单提供重新连接、关闭当前、关闭其他会话和关闭右侧会话；设置等页面标签至少提供关闭操作。重新连接会创建新的远程 Shell，不描述为恢复原进程。
- 设置等覆盖中央工作区的完整页面也进入同一标签栏，并以单例标签打开或聚焦。会话标签与页面标签共享选中、关闭和 `Cmd/Ctrl+W` 行为，关闭当前页面标签后返回最近保留的会话工作区。
- 文件面板开关固定在标签栏最右侧，使用 `24 × 24px` 单图标按钮；通过 Tooltip、可访问名称和按下状态表达打开或关闭，避免常驻文字占用标签空间。页面标签激活时禁用这一会话专属操作。
- 标签总宽度超出可用空间时保持单行并允许横向滑动，不显示滚动条轨道，也不得产生纵向滚动条或改变标签栏固定高度。新建或切换标签后，标签栏必须自动滚动到当前标签可见，但不能抢占终端输入焦点。
- 欢迎页和未连接页使用 `Empty`。启动后无会话的欢迎页不显示品牌图标，使用“开始一个远程会话”标题、单句工作区说明、一个“新建 SSH 连接”主操作和紧凑快捷键提示；其他空状态同样只保留一个主操作和至多一个次操作。
- 设置入口只位于应用全局栏；连接侧栏底部不再保留重复入口。

### 3.2 终端

- 终端占据中央区域，不增加常驻的大标题、卡片或工具栏。
- 搜索、清屏、重连、编码等低频操作放入快捷键、上下文菜单或轻量浮层。
- 终端搜索通过 `Cmd/Ctrl+F` 或右键菜单打开右上角紧凑浮层，输入时使用 xterm.js `SearchAddon` 增量高亮全部匹配项，并在滚动条概览区标记位置；Enter / Shift+Enter 跳转下一个 / 上一个结果，支持区分大小写，Escape 关闭并将焦点返回终端。搜索查询、结果位置和大小写选项属于单个会话状态，切换标签时保留，关闭搜索时清除高亮但保留查询以便再次打开。
- 终端右键菜单提供复制、粘贴、全选和清屏；复制在没有选择内容时禁用，粘贴在会话未连接或系统剪贴板不可用时禁用，菜单关闭后焦点返回当前 xterm。
- 当前连接信息由全局栏上下文、会话标签和状态栏共同表达，不在终端内容区重复展示。
- 多会话切换必须保留各自的滚动、选择和搜索状态；隐藏会话不重新创建终端实例。
- 首次连接的主机身份确认使用紧凑 `AlertDialog`：安全图标与标题同排，说明文字独占下一行；服务器、算法和 SHA-256 指纹统一放入低强调详情区域，指纹必须允许选择复制。

继续采用 xterm.js。它解决 ANSI/VT 序列、光标、选择、IME、可访问性和插件生态等终端渲染问题，自己用 React 或 Canvas 重写风险远高于收益。xterm.js 只负责终端仿真和绘制，SSH、PTY、原始字节流与会话生命周期仍完全属于 Rust。第一阶段先使用默认渲染路径；只有性能数据证明有必要时才启用 WebGL renderer。

### 3.3 SFTP 与传输

- 文件面板在软件每次启动时默认关闭。关闭期间建立 SSH 连接不读取远程目录，也不初始化 SFTP；用户主动打开后才连接当前会话的远程文件服务。面板保持打开时，切换或新建 SSH 会话会自动跟随当前会话，并在其连接成功后加载默认目录。
- 文件面板顶部只保留单行路径栏和文件表格。路径栏最左侧固定放置后退与前进按钮，其后为可点击面包屑；上传、下载、新建、刷新和窄屏关闭入口统一收进路径栏最右侧的三点操作 `Popover`。宽屏停靠面板默认宽 `360px`、最小宽 `340px`、最大宽 `600px`。表格行高 `32px`，列按名称、大小、修改时间排列。
- 文件和文件夹使用标准桌面文件管理器多选模型：普通单击替换选择，Shift 连续选择区间，macOS 使用 Command、Windows/Linux 使用 Ctrl 切换选中项，`Cmd/Ctrl+A` 全选，Escape 清空；方向键与 Home/End 移动键盘焦点，配合 Shift 扩展范围，Space 更新选中状态。多选时禁止误触仅支持单个目标的下载、重命名和删除。切换目录或 SSH 会话时清除旧目录的选中效果。文件夹使用鼠标双击进入；键盘聚焦目录后按 Enter 打开。路径面包屑和右键菜单中的“打开目录”保持单次激活。
- 上传和下载是可用的首要操作。普通文件和目录都能下载，符号链接和其他类型保持禁用；重命名和删除只出现在目标文件行的右键菜单中，目录读取或变更期间禁用。
- 路径栏三点操作菜单分别提供上传文件和上传文件夹入口；空白区域右键菜单同步提供两项。上传文件打开系统原生多文件选择器，上传文件夹打开系统原生单目录选择器；选择完成后不弹出额外确认层，逐文件任务立即进入全局传输浮层。上传成功后仅在用户仍查看目标目录时刷新文件列表。
- 下载普通文件时每次打开系统保存对话框；下载文件夹时每次打开系统目录选择器，并在所选位置下创建远端同名根目录。不提供或记忆固定下载目录。确认位置后任务直接进入全局传输浮层，不增加第二层确认；目标根目录已存在时明确拒绝合并或覆盖。
- 文件操作使用 `ContextMenu` 提供完整入口，路径栏三点 `Popover` 提供上传、单项下载、新建与刷新。面板空白区域菜单首先提供“新建”二级菜单，包含新建文件夹和新建空文件，其后提供上传与刷新。新建和重命名使用紧凑 `Dialog` 输入名称，确认后刷新当前目录；同名条目不能被静默覆盖。
- 文件行右键菜单为普通文件和目录提供“下载到…”，并继续提供重命名、复制路径、刷新和删除；目录额外提供打开入口。删除必须使用 destructive `AlertDialog` 二次确认；文件夹删除为非递归操作，只允许删除空文件夹。
- 传输队列使用全局栏传输按钮打开固定 `512 × 448px` 的 `Popover`。顶部展示任务总数与上传/下载数量、并发占用和整个队列 ETA，下面使用居中、紧凑的单选 `ToggleGroup` 分为“进行中、排队中、已暂停、失败、已完成”五栏；分栏文字内不混排数字，每个按钮左上角使用小型数量角标，自动重试属于排队中，取消记录归入已完成。长列表只在当前分栏内部滚动。任务行按方向图标、文件名与状态、连接与速率信息、进度和操作排列，运行与暂停任务的百分比置于进度条内；运行任务提供暂停与取消，暂停任务提供继续与取消。运行任务的连接、已传/总量、速度和 ETA 使用独立网格列，空间不足时只允许连接名优先截断，速度和 ETA 始终保留；方向、状态和操作同样使用固定宽度网格轨道，双操作按钮共用固定 `48px` 轨道，动态进度和断点更新不得移动状态或操作按钮。默认并发上限为 `3`，数据不足时 ETA 明确显示“估算中”。
- 全局栏按钮以计数或状态点提示活动、等待和失败任务。新传输只更新按钮摘要并使用轻量通知，不自动打开浮层打断终端输入。
- 传输浮层列表按“进行中、自动重试、等待、失败、最近完成”排序；等待和运行任务都能取消，瞬时失败最多自动重试两次。最终失败且可恢复的任务同时提供手动重试与“放弃重试”，后者必须释放两端目标授权，不能让旧失败任务长期占用保存位置。

### 3.4 设置

- 设置是中央工作区中的完整页面，不放进小型 Dialog。
- 设置由全局栏右侧图标按钮打开为工作区标签；重复点击只聚焦已有标签，不创建副本。返回会话通过点击对应会话标签完成，关闭设置使用标签叉号或 `Cmd/Ctrl+W`。
- 设置页“通用”区域提供“退出前确认”复选框。用户记住直接退出后可在此重新开启；读取和保存期间禁用控件，失败信息显示在字段内。
- 设置页“外观”区域提供“终端语义高亮”复选框，默认开启。关闭后只停用 Connex 附加的语义 decoration，不影响远端 ANSI、URL 悬停与链接打开能力。
- 设置页“外观”区域提供全局配色选择器，使用六项紧凑 `ToggleGroup` 展示松柏绿、商务蓝、石墨灰、深海青、沉稳靛和暖岩棕。每项展示主色、淡选中态与工作区底色三级色点；切换后立即应用到整个应用并持久化，保存失败时回滚原方案。
- 设置页“外观”区域提供终端字体选择器和“导入字体”操作。选择器依次列出七个常用预设、本机等宽字体和已导入字体，支持按字体族名称搜索；本机列表在首次打开时加载。未安装的系统字体预设保留在列表中，标记“未安装”并禁止选择；从其他设备恢复了不可用的已保存预设时，字段内必须明确说明已回退到 System Monospace。只有导入文件名去掉扩展名后与预设名称完全一致（忽略大小写）时，对应预设才恢复可选并标记“第三方资源”；带 `Regular`、`Bold` 等额外后缀的名称不得自动匹配。导入完成后仍选中“已导入”分组中的独立字体项，不自动切换预设。导入支持不超过 10 MiB 的 TTF、OTF、WOFF 和 WOFF2。删除自定义字体必须使用 `AlertDialog`，只删除 Connex 保存的副本，不处理用户原始文件；删除当前预设使用的第三方资源前先切回默认字体。
- 字体设置上方提供只读 xterm.js 预览，固定展示 Ubuntu 欢迎信息、常用 URL、`user@host` 提示符、路径、命令选项和构建结果。预览必须复用正式终端的主题、字体、字重、字号与行距，并在设置变化后立即刷新；不得连接 SSH 或获取真实会话内容。
- 设置页“外观”区域提供 9–32 px 的终端字号设置，使用紧凑 `InputGroup` 组合减小按钮、数值输入、单位和增大按钮。另设“快捷键调整字号”复选框，默认开启；终端获得焦点时，macOS 使用 `Command +/-`，Windows 和 Linux 使用 `Ctrl +/-`，主键盘与数字键盘加减键都应可用。
- 打开设置只在视觉上隐藏会话工作区，不能卸载终端实例或关闭 SSH 会话；切回会话标签后重新适配当前终端尺寸并恢复焦点。
- 设置分类位于页面左侧，内容区使用标题、说明和 `Field` 组合；每个分组只解决一个主题。
- 设置卡片中的字段统一使用 `16px` 内边距；终端字重、字号和行距编辑器统一为 `144 × 32px`，数值区、单位/状态区和增减按钮使用固定轨道，动态内容不能改变编辑器宽度或数值输入区域宽度。
- 外观设置使用三项 `ToggleGroup`：跟随系统、浅色、深色。终端默认跟随应用主题；出现第二套真实终端主题时，将当前 profile 状态升级为单选选择器，选择结果使用稳定 profile ID 持久化。
- “连接备份”与外观设置并列为独立分组，使用两个紧凑操作入口打开导出或导入 `Dialog`，不把完整表单直接常驻在设置页。
- 导出 Dialog 必须要求导出密码和确认密码；凭据范围使用二选一 `ToggleGroup`，默认“包含密码和口令”，另一个选项为“仅连接信息”。v1 不复制私钥文件，仅迁移其路径与可选口令；未来若增加私钥文件打包，必须使用独立显式选项且默认关闭。没有导出密码时提交后显示字段错误。
- 导入 Dialog 先选择 `.connex-backup` 文件并输入导出密码，再展示连接数量、凭据包含情况和冲突数量。冲突处理使用“覆盖、跳过、保留两份”三项选择；导入完成前不关闭 Dialog，成功结果在原位置反馈。

## 4. 密度、字体与形状

以 `4px` 为基础间距单位。常用间距只使用 `4 / 8 / 12 / 16 / 24 / 32px`，不在业务组件中创造零散数值。

| 内容               | 规格          |
| ------------------ | ------------- |
| 连接名称与标签文字 | `11px / 16px` |
| 状态和辅助文字     | `12px / 16px` |
| 列表与紧凑控件     | `13px / 18px` |
| 表单与正文         | `14px / 20px` |
| 分区标题           | `16px / 24px` |
| 页面或 Dialog 标题 | `20px / 28px` |
| 工具栏与列表控件   | 高 `32px`     |
| 默认表单控件       | 高 `36px`     |
| 主要操作           | 高 `36–40px`  |

- UI 使用系统字体栈，不依赖网络字体：macOS 优先系统字体，Windows 优先 Segoe UI，中文回退到系统中文无衬线字体。
- 终端默认字重 `500`，可调范围 `100–800`、步长 `100`；粗体自动比正文增加两档并封顶 `800`。默认字号 `13px`，可调范围 `9–32px`、步长 `1px`；默认行距 `1.10`，可调范围 `1.00–2.00`、步长 `0.05`。七个常用预设固定为 Fira Code、JetBrains Mono、Cascadia Code、Source Code Pro、SF Mono / Menlo、Consolas 和 System Monospace，默认使用 JetBrains Mono。
- Fira Code、JetBrains Mono、Cascadia Code 和 Source Code Pro 使用仓库本地可变字体并保留 OFL 许可证，不从网络加载；SF Mono / Menlo 和 Consolas 只引用操作系统已安装字体，缺失时进入系统等宽回退栈。字体族通过 `terminalFontProfiles.ts` 注册，Rust 通过 `font-kit` 只枚举本机等宽字体，用户字重作为独立偏好保存；后续增加预设只添加字体资源和 profile，不能在设置组件或 `TerminalPane` 中增加字体名称分支。
- 用户字体、字重、字号和行距只应用给 xterm.js 的 `fontFamily`、`fontWeight`、`fontWeightBold`、`fontSize`、`lineHeight`，不得修改 `--font-ui`、`--font-terminal` 或设置页等应用界面字体。字体异步加载或文字度量变化后刷新并重新 fit 现有终端，不重新连接 SSH。单字重自定义字体可能无法响应字重调整，界面说明和预览必须如实反映字体能力。
- 全局圆角基准为 `8px`。输入框和按钮使用 `6–8px`，卡片和浮层使用 `8–12px`；停靠面板和表格行不增加独立圆角。
- 停靠区域只用 `1px` 边框分层；阴影仅用于 Popover、Dropdown、Sheet 和 Dialog。
- 图标统一使用 Lucide。常规图标视觉尺寸 `16px`，紧凑辅助图标 `14px`；单图标按钮必须带 Tooltip 和可访问名称。

## 5. 主题模型

主题模式只有三个稳定值：`system`、`light`、`dark`，默认 `system`。

1. 启动时先根据系统 `prefers-color-scheme` 绘制，避免空白或固定暗色闪烁。
2. 根节点使用 `:root` 表示浅色，`.dark` 表示深色，并同步正确的 `color-scheme`。
3. `system` 模式持续监听系统主题变化；用户选择固定主题后不再响应系统变化。
4. 明暗模式与全局配色属于非敏感应用外观设置。允许在 localStorage 镜像首帧关键值，在 React 挂载前恢复；全局配色仍以 Rust/SQLite 设置存储为最终来源。
5. 主题变化同时更新 WebView、xterm 主题和 Tauri 原生窗口外观，不能出现浅色外壳配深色原生控件。

主题或全局配色切换不重新挂载终端、文件列表或会话，只更新语义 token 和 xterm theme adapter。

## 6. 语义配色

所有颜色通过 `src/styles/globals.css` 中的 CSS 变量暴露。业务组件只能使用语义类，例如 `bg-background`、`text-muted-foreground` 和 `border-border`，不能使用 `text-zinc-*`、十六进制色或独立 RGB/OKLCH 值。

中性基础 token 固定如下；`card-foreground` 和 `popover-foreground` 分别跟随 `foreground`，除非经过整体主题评审后修改。`primary`、`primary-foreground`、`secondary`、`secondary-foreground`、`accent`、`accent-foreground`、`ring`、`sidebar` 和 `workspace` 由当前全局配色 profile 为浅色与深色分别注入。

| Token                    | 浅色 `:root`             | 深色 `.dark`             | 用途                 |
| ------------------------ | ------------------------ | ------------------------ | -------------------- |
| `background`             | `oklch(0.985 0.003 264)` | `oklch(0.145 0.008 265)` | 应用基础背景         |
| `foreground`             | `oklch(0.205 0.012 264)` | `oklch(0.940 0.008 265)` | 主要文字             |
| `card`                   | `oklch(1 0 0)`           | `oklch(0.180 0.009 265)` | 卡片与抬升表面       |
| `popover`                | `oklch(1 0 0)`           | `oklch(0.190 0.010 265)` | 浮层                 |
| `primary`                | profile                  | profile                  | 主操作、活动指示     |
| `primary-foreground`     | profile                  | profile                  | 主色表面文字         |
| `secondary`              | profile                  | profile                  | 次级控件表面         |
| `secondary-foreground`   | profile                  | profile                  | 次级控件文字         |
| `muted`                  | `oklch(0.955 0.006 264)` | `oklch(0.220 0.010 265)` | 弱化表面             |
| `muted-foreground`       | `oklch(0.490 0.015 264)` | `oklch(0.680 0.012 265)` | 辅助文字             |
| `accent`                 | profile                  | profile                  | hover、选中项        |
| `accent-foreground`      | profile                  | profile                  | accent 表面文字      |
| `destructive`            | `oklch(0.560 0.200 27)`  | `oklch(0.640 0.200 25)`  | 删除与严重错误       |
| `destructive-foreground` | `oklch(0.985 0 0)`       | `oklch(0.140 0.010 25)`  | destructive 表面文字 |
| `border`                 | `oklch(0.900 0.008 264)` | `oklch(0.270 0.012 265)` | 分隔线与边框         |
| `input`                  | `oklch(0.860 0.010 264)` | `oklch(0.290 0.012 265)` | 输入边框             |

| `terminal`               | `oklch(0.992 0.002 264)` | `oklch(0.115 0.008 265)` | 终端背景             |

状态色独立于品牌主色，必须同时配合图标、文字或形状表达，不能只靠颜色区分：

| 状态          | 浅色                     | 深色                     | 使用场景                 |
| ------------- | ------------------------ | ------------------------ | ------------------------ |
| `success`     | `oklch(0.490 0.140 151)` | `oklch(0.740 0.150 151)` | 已连接、传输完成         |
| `warning`     | `oklch(0.530 0.140 75)`  | `oklch(0.800 0.150 80)`  | 等待确认、网络不稳定     |
| `info`        | `oklch(0.520 0.140 250)` | `oklch(0.740 0.140 250)` | 连接中、传输中           |
| `destructive` | 使用核心 token           | 使用核心 token           | 认证失败、连接错误、删除 |

连接状态映射固定为：未连接使用 `muted-foreground`，连接中使用 `info` 和旋转图标，已连接使用 `success`，需要确认使用 `warning`，失败使用 `destructive`。正常正文仍使用 `foreground`，状态色不用于长段文字。

窗口按钮不属于 WebView 语义配色范围。各平台原生窗口装饰的颜色、状态和交互完全交由操作系统管理，应用不得为其定义 CSS token。

## 7. 终端配色

xterm theme adapter 从当前应用主题读取 `terminal`、`primary` 和 selection token，并从终端 profile 读取正文前景色后注入 xterm.js。Connex Neutral 的浅色正文使用 `#15171A`，深色正文使用 `#E8E9ED`；默认 ANSI 16 色保持固定，避免不同功能自行选择不一致的主题。

终端主题以 profile 注册；每个 profile 同时提供浅色/深色正文前景色、ANSI palette 和语义 palette。文本识别规则与 profile 解耦，不得为不同主题复制正则或 buffer 扫描逻辑。当前唯一 profile ID 为 `connex-neutral`，用户选择能力等出现第二套真实主题后再开放。

## 9. 交互状态、无障碍与动效

- hover、focus-visible、active、selected、disabled、loading 和 error 都必须有明确且一致的状态。
- 键盘焦点使用 `2px` ring；不能用 `outline: none` 后不提供替代焦点样式。
- 正文与背景对比度至少 `4.5:1`，大号文字和关键图标至少 `3:1`。
- 图标按钮必须有 `aria-label`；破坏性动作写清目标名称；进度变化提供可读文本而不只显示进度条。
- 常用工作流提供键盘路径：新建连接、切换会话、关闭会话、终端搜索和打开文件面板。
- hover 过渡使用约 `120ms`，面板展开使用约 `180ms`，Dialog/Sheet 使用约 `200–240ms`。只动画 opacity 和 transform，遵循 `prefers-reduced-motion`。
- 连接或传输状态变化不造成布局跳动。状态文本区域预留空间，进度更新不能抢走终端焦点。

## 10. 实施顺序与防漂移规则

后续前端工作按以下顺序推进：

1. 建立 `system / light / dark` provider、启动主题恢复和完整 CSS token。
2. 把应用壳改为可调整面板，并实现宽屏停靠与紧凑窗口 Sheet 策略。
3. 逐步用组件映射表中的 shadcn 原语替换现有临时结构。
4. 接入真实 xterm 实例时实现唯一的 theme adapter。
5. 在真实 SFTP 和传输功能中补齐状态、空态、错误与键盘交互。

以下规则属于合并前检查项：

- 新视觉值必须先判断能否复用现有 spacing、radius 或颜色 token。
- 全局主题值只在 `src/styles/globals.css` 定义；xterm 正文前景色、ANSI 与语义 palette 只在 `terminalThemeProfiles.ts` 定义。
- 新布局不得绕过本文规定的面板层级和宽度让渡顺序。
- 对布局、主题、状态映射或组件基线的有意变更，必须与本文同一提交更新。
- 每完成一个用户可见模块，都要在浅色、深色和跟随系统三种模式下做一次本地渲染检查。
